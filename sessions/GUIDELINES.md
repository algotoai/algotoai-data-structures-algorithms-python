# How Sessions Are Written

These guidelines keep every session in this course consistent and beginner-friendly.

## Simple First, Advanced Later *(proposed)*

Start each session with the **simplest correct code** that shows the idea. Bring in more advanced Python only in a later session that explains it first.

- The first example should fit on one screen and use only what the learner already knows.
- If a feature adds complexity without helping the session's one objective, leave it for a later session.
- Explain ideas in plain English **outside** the code. Keep comments in the code to a minimum.
- State any assumption in the text instead of handling it with new syntax (for example, "the list has at least one number").
- Checkers and tests support the learner, but are never required reading.

## Every session

- One clear learning objective, built around one main example.
- **Exam Ready:** trace by hand, predict results, answer university-style questions.
- **Job Ready:** write and run code, change the input, check the results, and grow toward tested, professional code over the course.
- Accurate examples: every expected output in the text is checked by running the code.
- Runs with plain Python. Nothing extra to install.
